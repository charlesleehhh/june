## 抓取失败后的改造（第二轮，13:00-13:30）

**用户反馈**：服务器上跑 `java -jar price-radar-crawler.jar config.properties`，
apple 解析 0 条、jd connect timed out、status=FAIL。用户要求 readme 跟着部署目录调整，
并问「价格抓取都失败了，有别的办法么」。

**实测结论（全部不可自动抓取，务必记住）**：
- Apple 官网购买页：HTTP 200、527KB，页面内 0 个价格（JS 渲染）
- 京东 p.3.cn：TLS 握手被拒（"Remote host terminated the handshake"）；明文 HTTP 直接不通
- 京东商品页：200 但仅 36KB，价格不在 HTML 里；搜索接口 api.m.jd.com 需 appid+签名
- 结论：apple.enabled / jd.enabled 默认改为 false，官方价在库里维护

**本轮新增代码**：
- `Http.java` 统一网络层（重试/代理/UA/诊断 dump）；`Db.reason()` 把 JDBC 异常压成一句人话；
  Db 构造自动追加 connectTimeout=8000/socketTimeout=60000，库不可达 20s 内失败退出，不挂死 cron
- `Diagnose.java` → `--diagnose`：DNS→TCP→HTTP→解析四层诊断
- `AdminServer.java` + `resources/admin.html` → `--serve`：管理员后台，JDK 内置 HttpServer，
  绑定 127.0.0.1:8099，价格录入表格（只填变动格子）→ 写库 + 立即重生成 prices.json；
  另有大事记整体编辑、导出 CSV。三层鉴权：仅绑本机 + nginx Basic Auth + 程序内 Basic Auth
  （本地实测 401/401/200 通过）
- `DbInit.java` → `--init-db schema.sql`：一键建表导入种子（服务器无需 mysql 客户端）
- `Ingest.java` → `--ingest prices.csv|json`：离线批量导入
- `MailFetcher.java`：IMAP 解析平台降价通知邮件（覆盖拼多多/得物），mail.enabled 默认 false
- JsonGenerator 抽成独立类，供主流程/后台/导入复用
- .gitignore 补 `backend/dependency-reduced-pom.xml`、`.idea/`，并 `git rm --cached` 两者
